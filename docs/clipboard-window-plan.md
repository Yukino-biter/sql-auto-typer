# 独立输入窗口（1.0.2）

原因：头歌当前编辑器的禁止复制逻辑在获得焦点及初始化时调用 `navigator.clipboard.writeText(" ")`，覆盖系统剪贴板。插件原有代码不读写剪贴板。

采用独立扩展窗口接收草稿。窗口先绑定原 HTTP / HTTPS 标签页；用户随后在外部复制，直接回独立窗口粘贴。开始时先捕获完整 SQL，再激活原网页并提交任务；窗口在后台成功接收后关闭。仍需倒计时内点击编辑区。目标已关闭或无效时保留草稿并显示错误，不改投其他标签页。

不新增剪贴板权限、不拦截或改写网站的剪贴板函数、不持久保存 SQL。此工作流保护本次输入的文本，无法阻止网站日后覆盖系统剪贴板，也不能恢复已经丢失的文本。普通弹窗保持可用；已有文本时拒绝直接打开新窗口，并保留草稿、提示先处理文本，以免原弹窗自动关闭导致丢稿。

验证：先增加并观察缺少独立窗口的回归测试失败，再验证真实 MV3 窗口的目标绑定、模拟网站焦点清空剪贴板后的 SQL 保真、目标关闭时草稿保留，以及现有输入、中断和模型选项恢复测试。模拟剪贴板使用测试变量，不访问用户系统剪贴板。

现场证据：排查时页面 React 属性 `forbidCopy: true`，编辑区的 `onFocus` 调用清空函数。页面加载的[头歌第一方脚本](https://www-cdn.educoder.net/35511.15ce162e.async.js)中，该函数调用 `navigator.clipboard.writeText(" ")`，并由初始化、编辑器 focus 回调和容器 onFocus 触发。本结论针对当前排查页面的版本，其他实训和后续平台版本可能不同。未读取或修改用户系统剪贴板。

焦点处理：明确切换到其他浏览器窗口时仍立即暂停；只有关闭独立窗口可能产生的 `WINDOW_ID_NONE` 短暂事件，才重新查询目标窗口的实际焦点，避免误暂停。
