# SQL 逐字输入

把 SQL 粘贴到插件窗口，点击开始，在倒计时内点击网页编辑区；插件通过浏览器输入接口逐字输入。可用于头歌等禁止复制粘贴、但仍允许键盘输入的网页场景。主要面向普通网页及代码编辑器，默认间隔 100 毫秒。

## 安装（无需 npm 或编译）

1. 在 GitHub 仓库中点击 **Code → Download ZIP**，下载并解压源码，或使用 Git 克隆仓库。
2. Edge 打开 `edge://extensions`；Chrome 打开 `chrome://extensions`。
3. 开启“开发人员模式”，点击“加载解压缩的扩展”。
4. 选择解压后源码中的 **`extension` 文件夹**，其中包含 `manifest.json`。
5. 在浏览器扩展菜单中固定“SQL 逐字输入”。

如果你已有打包版本 `SQL逐字输入-1.0.2.zip`，则选择其中包含 `manifest.json` 的文件夹。打包版本可以通过下方开发者命令生成。

旧版用户：用新版文件覆盖原加载文件夹中的文件，然后在扩展管理页点击“重新加载”，再开启扩展。版本号应显示 **1.0.2**。如果选择新的加载文件夹，请保持旧版关闭，避免两个版本同时运行。

插件需要 debugger 权限，浏览器可能显示正在调试页面的提示；这是逐字输入所用的浏览器接口。停止或完成后插件释放连接。无需关闭粘贴限制、修改网站代码或安装桌面程序。

## 在头歌上使用

1. 打开实训中的网页代码编辑器，先手动输入确认可以编辑，并放好光标。需要替换原代码时自行选中相应内容。
2. 点击插件中的 **“打开独立输入窗口”**。该窗口会绑定当前网页，显示目标标题。
3. **然后去外部复制 SQL，直接回到独立输入窗口粘贴，中途不要先切回头歌。** 已经变成空格的剪贴板内容需要重新从来源复制。
4. 先用少量 SQL 验证，例如 `SELECT 1;`。需要时将倒计时调到 5–10 秒。
5. 点击“开始输入”，插件先接收全文，再自动返回原网页。请在倒计时内点击 SQL 编辑区。
6. 图标显示进度。按 `Alt+Shift+P` 暂停 / 倒计时继续，`Alt+Shift+X` 停止；也可以重新打开插件操作。
7. 完成后检查代码，再自行保存、提交或执行。插件不会发送 Enter、Tab、执行或提交快捷键。

**为什么外部复制的内容会变成空格？** 当前排查的头歌编辑器在启用禁止复制时，会在初始化及获得焦点时调用 `navigator.clipboard.writeText(" ")`，覆盖系统剪贴板，因而其他软件粘贴也只剩空格。独立窗口让插件先接收 SQL，再切回目标网页；后续剪贴板变化不会改变这次输入任务。它不会阻止网站继续改写系统剪贴板，也不能恢复已经覆盖的原文。原因和证据见 [排查记录](https://github.com/Yukino-biter/sql-auto-typer/blob/main/docs/clipboard-window-plan.md)。

普通网页仍可直接使用插件弹窗粘贴并开始。普通弹窗已有文本时，“打开独立输入窗口”会提示先处理草稿，避免原弹窗关闭导致文本丢失。独立窗口关闭前未开始的草稿只存在该窗口中；目标页已关闭时会保留草稿并报错，不会输入到其他标签页。

头歌不同实训的编辑器可能不同。当前支持文本框、可读取模型的 CodeMirror 5、Monaco、Ace，以及 contenteditable。1.0.1 支持头歌组件内部保存的 Monaco 实例，不再要求页面暴露 window.monaco。已在用户的“DML语言的使用 / 第1关：插入数据”真实页面验证编辑器识别与浏览器文本输入，并核对中文、缩进、Tab、引号和换行；测试后恢复了原代码与编辑器设置，未提交或执行。其他实训仍需逐页确认。截图中的 VNC / 远程桌面不在此版本范围内。

Chrome 新标签页（即使显示 Google 图标和搜索框）及浏览器地址栏不支持。真正的 `https://www.google.com/` 网页搜索框属于普通网页文本框；输入前应确认地址栏是 HTTP / HTTPS 地址。弹窗中的灰色 SQL 是占位示例，字符数为 0 时必须先粘贴实际文本。

## SQL 保真与中断

- 保留开头和结尾的空白、缩进、Tab、单双引号、注释、中文和 Emoji。
- Windows CRLF / CR 换行统一为网页使用的 LF，不格式化 SQL、不增加语句。
- 每个字符经浏览器文本输入接口提交，不使用剪贴板粘贴，不直接赋值输入框或修改代码模型。
- 原生文本框、可读取模型的编辑器逐字核对内容和光标。自动缩进 / 自动补全造成差异时暂停。
- Monaco 在输入期间暂时关闭自动缩进、引号 / 括号补全和输入格式化，暂停、完成或停止时恢复。意外断开连接时，网页守卫在约 6–7 秒后恢复；后台页面计时器受浏览器节流时可能更迟。
- 普通富文本只监测焦点和选区，无法保证复杂 DOM 中的缩进和内容完全一致，界面会标明需要自行检查。
- 切换标签页 / 窗口、目标失去焦点、改变内容或光标时暂停。回到**原位置**后继续；页面刷新、关闭或连接断开后必须重新开始。
- 暂停时若最后一个字符已在发送途中，它可能完成写入；停止后不会发送下一字符。
- 连接报错时不自动重试，以免重复最后一个字符。先核对目标，再从剩余文本重新开始。
- 1.0.1 为浏览器连接、编辑区读取及字符输入加入了 5 秒超时；停止时先尝试释放连接，避免等待卡住的命令。超时不代表最后一个字符一定未写入，请核对后重新开始。
- 单行框遇到换行或 Tab 时暂停；改用多行编辑区。密码框、只读区域、浏览器内部页面及当前未适配的跨域 iframe 不支持。
- 浏览器重启、扩展更新或重新加载后，任务不恢复。

## 本地数据

SQL 只保留在弹窗、独立输入窗口和运行任务的内存中，不写入 storage，不上传网络。插件仅持久保存速度和倒计时设置。完成 / 停止后清空后台任务文本；关闭输入窗口会清空其中尚未开始的草稿。

## 测试和打包（开发者）

需要 Node.js 20 或更新版本。

```powershell
npm install
npm test
npm run test:browser
npm run package
```

浏览器测试加载真实 MV3 扩展，并在拦截粘贴的本地测试页面上检查内容和事件。测试脚本使用 Playwright 浏览器；若默认路径不存在，先安装 Chromium，再通过 `SQL_TYPER_BROWSER` 环境变量指定可执行文件。

```powershell
npx playwright install chromium
$env:SQL_TYPER_BROWSER = '实际的 Chromium chrome.exe 路径'
npm run test:browser
```

`tests/fixture.html` 使用仅作为开发依赖的 CodeMirror 和 Monaco，它们不会进入插件安装包。
